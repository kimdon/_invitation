# 개발자 모드 통합 구동 화면 설계

## 목표

개발자 모드 진입 시 Git 전환 로그와 애플리케이션 구동 로그를 하나의 전체 화면 터미널에서 연속으로 보여준다. 마지막 `SUCCESS` 로그가 출력된 뒤 터미널을 닫고 `Invitation` 본문으로 전환한다.

## 사용자 흐름

1. 사용자가 `develop mode` 버튼을 누른다.
2. 전체 화면 터미널이 열리고 Git 전환 명령과 결과가 순서대로 출력된다.
3. 같은 터미널에 하트 로고와 웨딩 애플리케이션 구동 로그가 이어서 출력된다.
4. `DEBUG`, `WARN`, `INFO`를 포함한 기존 로그와 마지막 `SUCCESS wedding-v1.0 deployed ♥`를 모두 보여준다.
5. `SUCCESS`를 약 0.6초 유지한 뒤 터미널이 0.45초 동안 페이드아웃된다.
6. 개발자 모드의 `Invitation` 본문이 최상단에서 페이드인된다. 자동 스크롤은 실행하지 않는다.

## 화면 구성

- 기존 Git 전환 오버레이를 통합 구동 화면으로 사용한다.
- Git 로그를 지우지 않고 구동 로그를 같은 로그 영역 아래에 이어 붙인다.
- 하트 로고와 `OUR WEDDING`, `wedding-v1.0`, 두 사람의 이름은 통합 구동 화면에 배치한다.
- 전환 후 개발자 모드에서는 별도의 전체 화면 커버를 노출하지 않고 `Invitation`부터 보여준다.
- 일반 모드의 사진 커버와 기존 내용은 변경하지 않는다.
- `Invitation`의 Git 용어는 기존 파란색과 굵기를 유지하되 밑줄은 제거한다.

## 상태와 접근성

- `switching` 상태 동안 통합 터미널만 노출하고 본문은 숨긴다.
- 로그 영역의 `role="log"`, `aria-live="polite"`, `aria-busy` 상태를 유지한다.
- `SUCCESS` 이후에만 개발자 본문을 접근 가능하게 전환한다.
- 움직임 최소화 설정에서는 모든 지연과 애니메이션을 생략하고 즉시 최종 상태를 보여준다.

## 검증 기준

- Git 전환 로그와 구동 로그가 동일한 전체 화면 로그 영역에 함께 남는다.
- 구동 중에는 개발자 본문이 보이지 않는다.
- 마지막 로그는 `SUCCESS wedding-v1.0 deployed ♥`이다.
- 완료 후 `Invitation`이 첫 화면으로 나타나며 자동 스크롤이 발생하지 않는다.
- 개발자 모드의 Git 용어에는 색상만 적용되고 밑줄은 없다.
- 일반 모드, 승인 버튼, 폭죽, 지도, 갤러리, 계좌 기능은 기존대로 동작한다.
- 자동화 테스트, 문법 검사, 모바일 브라우저 검증이 모두 통과한다.
