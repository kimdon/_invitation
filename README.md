# 모바일 청첩장

첨부된 PDF 디자인을 기준으로 만든 정적 모바일 청첩장입니다.

## 로컬 실행

저장소 루트에서 다음 명령을 실행합니다.

```bash
python3 -m http.server 4173
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다.

자동 테스트는 다음 명령으로 실행합니다.

```bash
npm test
```

## 사진 파일

- 대표 사진: `images/cover.webp`
- 일반 모드 갤러리: `images/gallery/`의 기존 웨딩 사진 18장을 사용합니다. `src/invitation.js`의 `GALLERY_PHOTOS`에 있으며 `IMG_5000.JPG`부터 번호 오름차순입니다.
- 개발자 모드 갤러리: `images/gallery/develop-mode/`의 일상 사진 9장을 사용합니다. `DEVELOPER_GALLERY_PHOTOS`에 있으며 `IMG_200.HEIC`부터 번호 오름차순입니다. 썸네일과 확대 화면 모두 현재 모드의 사진 목록을 사용합니다.
- 두 모드 모두 처음 3장만 표시하고 `더 보기`로 해당 모드의 전체 사진을 펼치거나 `접기`로 다시 접습니다. 페이지 이동 버튼과 숫자는 표시하지 않으며 모드를 전환하거나 재진입하면 다시 기본 3장으로 접습니다. 개발자 사진은 개발자 모드에 진입할 때부터 불러옵니다.
- 나머지 썸네일은 처음 펼칠 때 생성해 지연 로딩하고 다시 펼칠 때 재사용합니다. 접힌 사진은 키보드 탐색과 화면 읽기에서 제외합니다. 더 보기 버튼은 투명 배경·테두리 없이 표시하고, 아래 설명과의 여백은 4px입니다.
- 별도 확대 화살표 없이 사진 전체를 누르면 크게 열립니다. 키보드로 사진에 초점을 맞춘 뒤 Enter 또는 Space로도 열 수 있습니다.
- 사진을 추가하거나 제외할 때는 해당 모드의 사진 목록도 함께 수정합니다. 목록에 입력한 위치와 관계없이 사진 번호순으로 표시합니다.
- 갤러리 썸네일 파일이 없으면 깨진 이미지 대신 자리표시자가 표시됩니다.
- 전체 화면 뷰어는 다음 사진의 로딩과 디코딩이 완료될 때까지 현재 사진을 유지한 뒤, 겹치지 않는 두 화면을 160ms 동안 좌우로 이동합니다. 로딩 안내 문구는 표시하지 않고 실제 오류만 안내합니다. 동작 줄이기 설정에서는 애니메이션을 생략합니다.
- 뷰어를 연 뒤 현재 사진과 앞뒤 사진만 준비·재사용합니다. 멀어진 사진과 닫은 뷰어의 캐시는 해제하며, 데이터 절약 모드나 2G 연결에서는 미리 불러오지 않습니다.
- 여러 손가락을 모두 뗄 때까지 사진 이동을 무시합니다.

### 갤러리 최적화

일반 모드의 원본 JPG와 `images/gallery/develop-mode/`의 원본 JPG·HEIC는 로컬로 보존하고 Git에서 제외합니다. 배포에는 `images/gallery/optimized/`의 WebP만 포함합니다. 개발자용 변환본은 그 아래 `developer/`에 분리합니다.

- `thumbnails/`: 긴 변 최대 480px, 품질 78. 갤러리 근처로 스크롤하면 불러옵니다.
- `full/`: 긴 변 최대 1,800px, 품질 85. 뷰어를 연 뒤 현재 사진과 인접 사진을 불러옵니다.
- 원본의 종횡비를 유지하고 EXIF 회전 정보를 반영합니다. 출력 파일에서는 촬영 메타데이터를 제거합니다.

원본 사진이나 목록을 변경한 뒤에는 다음 명령으로 표시용 이미지를 다시 생성합니다.

```bash
npm install
npm run optimize:gallery
```

개발자 모드 사진만 변환하려면 아래 명령을 실행합니다. macOS에서는 기본 제공 `sips`로 HEIC를 임시 PNG로 해석한 뒤 WebP를 만들고 임시 파일을 정리합니다. 원본은 수정하지 않습니다. 원본이 다른 작업 폴더에 있으면 `--source-dir=원본폴더경로`를 추가할 수 있습니다.

```bash
npm run optimize:gallery -- --mode=developer
```

변환 도구는 개발 시에만 사용합니다. 청첩장은 생성된 WebP를 포함하는 정적 사이트로 실행됩니다.

### 화면 조작과 반응 속도

일반·개발자 모드와 팝업 전체에 확대 방지를 적용합니다. 세로 스크롤과 일반 버튼 조작은 유지하면서 핀치, 더블 탭, 트랙패드 확대와 페이지 확대 단축키를 막습니다. 브라우저 메뉴나 운영체제 접근성 확대까지 강제로 차단할 수는 없습니다.

대표 사진은 HTML에서 우선 로딩합니다. 갤러리 펼치기는 360ms, 접기는 480ms, 본문 등장은 300ms로 동작하며 동작 줄이기 설정에서는 애니메이션을 생략합니다. 접을 때 갤러리 제목이 화면 위로 벗어나 있다면 사진 높이가 줄어드는 진행률에 맞춰 스크롤도 함께 이동합니다. 접기 전에 제목으로 순간 이동하지 않으며, 제목이 이미 보이면 화면 위치를 유지합니다. 본문 감지는 IntersectionObserver만 사용해 스크롤마다 위치를 반복 계산하지 않습니다. 기존 개발자 구동 로그와 완료 후 1초 대기는 유지합니다.

개발자 모드는 `[INFO] develop mode` 헤더와 `// invitation`부터 시작하며 대표 사진을 표시하지 않습니다. 초대 문구는 기존 branch·commit·conflict·resolve·merge·approve 이야기로 표시하고, 예식 정보·지도·계좌 내용은 일반 모드와 공유합니다. 갤러리의 동작은 공유하되 개발자 모드에는 별도의 일상 사진을 표시합니다. 고정폭 글꼴·로그 주석·터미널 색상을 사용하며 기존 AI 승인 리뷰, 1회 APPROVE와 폭죽, 재진입 시 승인 초기화는 유지합니다.

두 모드의 전환 버튼은 높이 44px, 모서리 10px, 20px 아이콘과 13px 문구, 입체 테두리·눌림 효과를 공유합니다. 일반 모드는 기존 흰색/회색, 개발자 모드는 터미널 초록색 계열을 사용하며 키보드 포커스 표시와 동작 줄이기 설정을 지원합니다.

개발자 모드에서 APPROVE를 누르면 폭죽 애니메이션만 표시하며 별도의 효과음은 재생하거나 불러오지 않습니다. BGM의 재생 상태·음량·곡 순서는 그대로 유지합니다.

## 배경음악

BGM 출처: [네이버 블로그 원문](https://m.blog.naver.com/PostView.naver?blogId=hae_mosu&logNo=224214506343&proxyReferer=https%3A%2F%2Fwww.google.com%2F&trackingCode=external)

페이지 진입 시 아래 첫 곡부터 소리 있는 자동재생을 시도합니다. 한 곡이 끝나면 다음 곡을 재생하고, 두 번째 곡이 끝나면 첫 곡으로 돌아가 이 순서를 계속 반복합니다.

1. `모험떠나야할것같은지브리＿김빵식.mp3` → `bgm/adventure.mp3` (기본 시작 곡)
2. `잔잔한＿김빵식.mp3` → `bgm/wedding.mp3`

두 배포 파일은 제공된 원본의 복사본이며 원본 음원은 수정하지 않습니다. 하나의 오디오 요소에서 곡이 끝날 때 파일만 교체하며, 단일 곡 반복 속성은 사용하지 않습니다. 새로 진입하거나 새로고침하면 첫 곡부터 시작합니다.

모바일 등에서 브라우저가 자동재생을 막으면 첫 화면 터치·클릭 또는 Enter/Space 입력 시 다시 시도하며, 오른쪽 위 음악 버튼으로도 시작할 수 있습니다. 브라우저·인앱 앱 정책에 따라 진입 즉시 재생을 보장할 수는 없습니다. 버튼으로 일시정지한 뒤에는 다른 곳을 터치해도 다시 켜지지 않으며, 버튼을 다시 누르면 이어서 재생합니다. 일반·개발자 모드는 오디오 하나를 공유하므로 모드 전환 시 재생 위치를 초기화하지 않습니다. 기본 음량은 35%로 요청하지만 기기에서 소프트웨어 음량을 지원하지 않으면 기기 음량을 따릅니다.

## 계좌 안내

일반·개발자 모드의 `마음 전하실 곳`은 신랑측·신부측 카드를 각각 펼쳐 가족 세 명의 계좌를 확인하는 방식입니다. 이름·은행·계좌번호와 복사 버튼만 제공하며, 은행 앱 실행이나 송금 서비스는 연동하지 않습니다. 현재 여섯 계좌는 기존 임시값을 사용합니다. 데이터는 `src/invitation.js`의 `ACCOUNT_GROUPS`에서 관리합니다.

두 모드에서 계좌를 팝업 없이 본문 안에 표시합니다. 최초 진입과 모드 전환 시 신랑측·신부측 카드는 모두 접힌 상태로 시작하며, 사용자가 누른 카드만 펼칩니다. 접힌 카드 내용은 키보드 탐색과 화면 읽기에서 제외하고, 동작 줄이기 설정에서는 펼침 애니메이션을 생략합니다.

계좌번호를 복사하면 해당 버튼의 아이콘만 1.8초 동안 체크 표시로 바뀐 뒤 원래대로 돌아옵니다. 화면에 완료 문구를 띄우지 않으며, 화면 읽기 기능에는 복사 완료를 안내합니다.

## 지도와 길찾기 버튼

현재 지도 API 호출은 임시 중지 상태입니다. `setupVenueMap()`은 기본적으로 SDK와 지도 타일을 요청하지 않습니다. 일반·개발자 모드 모두 지도 영역에 저장된 약도 이미지(`images/venue-map.png`)를 표시합니다. 예식장 안내와 카카오맵·네이버지도·TMAP 길찾기 버튼은 유지합니다. 재개하려면 `src/app.js`의 호출을 `setupVenueMap({ enabled: true })`로 변경합니다. 이미 열린 화면에는 새로고침 이후 적용됩니다.

활성화하면 Location에 네이버 Dynamic Map을 표시합니다. 브라우저용 Client ID는 `src/venue-map.js`에 있으며 Client Secret은 사용하거나 저장하지 않습니다. Naver Cloud의 Web 서비스 URL에 배포 도메인 `https://kimdon.github.io`와 로컬 미리보기 주소를 등록해야 합니다. [공식 SDK 안내](https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html)의 `ncpKeyId` 인증 방식을 사용합니다.

지도는 Location 300px 전부터 한 번만 불러오고, 예식장 공식 홈페이지의 네이버 길찾기 목적지 좌표(위도 37.5673842, 경도 126.827051)를 표시합니다. 중복 초기화와 자동 재시도는 하지 않으며 일반·개발자 모드 전환 시 기존 지도 크기만 갱신합니다. 스크롤을 가로채지 않도록 드래그·휠·핀치 확대를 끄고 지도 자체의 확대/축소 버튼을 제공합니다.

인증 실패(한도 초과 등을 포함할 수 있음), SDK/네트워크/초기화 오류 또는 지도 로딩 12초 초과 시 지도만 숨기고 같은 영역에 저장된 약도 이미지를 자동으로 표시합니다. 예식장 이름·주소·길찾기 버튼은 유지합니다. SDK의 공통 인증 실패 경로만으로 월 한도 초과 여부를 구분하지는 않습니다. 자동 재시도나 별도의 Static Map API 호출은 하지 않으므로 대체 약도를 보여주는 데 지도 API 사용량이 추가되지 않습니다. 정상 로딩 시에는 약도 이미지 대신 지도를 표시합니다. 실패 후 늦게 도착한 지도 응답은 약도를 다시 지도 화면으로 바꾸지 않습니다. 출처: [예식장 공식 오시는 길](https://www.botanicparkwedding.com/location), [공식 약도 PNG](https://cdn.imweb.me/thumbnail/20250706/a8b9d346f0424.png) (2026-09-26 확인).

이 최적화는 현재 페이지의 불필요한 요청을 줄이는 것이며 전체 계정 사용량이나 요금을 강제로 제한하지 않습니다. 새로고침·다른 방문자의 접속은 별도의 지도 요청을 발생시킬 수 있습니다. 계정의 실제 월 한도와 초과 사용 허용 여부는 Naver Cloud 콘솔에서 별도로 관리해야 하며, 페이지 코드는 해당 설정을 변경하지 않습니다.

Location 영역에는 카카오맵, 네이버지도, TMAP 버튼이 표시됩니다. 모든 버튼은
`보타닉 웨딩파크`를 검색하며 별도의 API 키가 필요하지 않습니다.
모바일에서는 각 앱의 검색 화면을 먼저 실행합니다. Android에서는 Intent의 대체 URL로 카카오/네이버 웹 검색 또는 TMAP Google Play 설치 화면을 지정합니다. TMAP은 통신사별 앱도 처리하도록 특정 패키지로 한정하지 않습니다.
iOS는 앱 URL Scheme을 사용하며, 앱이 열리지 않을 경우 사용자가 누를 수 있는 카카오/네이버 웹 검색 또는 TMAP App Store 설치 버튼을 함께 표시합니다. 인앱 브라우저에서 자동 대체가 지원되지 않는 경우에도 이 버튼을 이용할 수 있습니다.
앱 설치 여부나 인앱 브라우저의 실행 차단을 100% 판별할 수는 없습니다. 시간만 보고 강제 이동하는 타이머는 사용하지 않으며, 페이지가 숨겨지거나 떠날 때 대체 안내를 닫습니다. 따라서 앱에서 돌아온 뒤 뒤늦은 웹/스토어 이동을 예약하지 않습니다.
데스크톱에서는 카카오/네이버 웹 검색과 TMAP 공식 연결 페이지를 새 탭으로 엽니다. TMAP 공식 연결 페이지는 데스크톱에서 TMAP 웹사이트로 이동합니다.
카카오맵과 TMAP은 기존 앱/웹 길찾기 연결을 유지하며 별도 SDK를 불러오지 않습니다.

일반·개발자 모드 모두 버튼을 지도 바로 아래 가로 3등분 연결형으로 표시합니다. 높이는 44px, 아이콘과 글자 간격은 4px이며, 카카오맵·네이버지도 아이콘은 16px, TMAP은 14px입니다. 두 모드 모두 [참고 화면과 동일한 컬러 아이콘](images/map-icons/SOURCES.md)을 로컬에서 불러옵니다. 일반 모드는 [이롭게 바탕체의 버튼 글자 전용 웹폰트](fonts/SOURCES.md), 개발자 모드는 기존 터미널 색상·고정폭 글꼴을 사용합니다. 외부 이미지·폰트 서버는 호출하지 않습니다.

연결 형식 확인 출처: [카카오맵 URL Scheme](https://apis.map.kakao.com/ios_v2/docs/getting-started/urlscheme/), [네이버 지도 URL Scheme](https://guide.ncloud-docs.com/docs/maps-url-scheme), [TMAP 공식 검색 연결 페이지](https://www.tmap.co.kr/tmap2/mobile/search.jsp), [Chrome Android Intent](https://developer.chrome.com/docs/android/intents). TMAP의 공식 페이지 소스에서 iOS와 Android의 검색 파라미터 및 설치 경로를 확인했습니다.
